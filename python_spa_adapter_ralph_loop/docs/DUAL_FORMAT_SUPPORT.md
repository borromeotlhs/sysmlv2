# Dual Format Support: JSON IR and SysML v2

The SPA now supports loading and visualizing architectures in both JSON IR and SysML v2 textual formats.

## Overview

The system automatically detects file format and handles it appropriately:

- **JSON IR files** (`.json`) - Original intermediate representation format
- **SysML v2 files** (`.sysml`) - Textual SysML v2 syntax

Both formats work seamlessly with all SPA features:
- File tree navigation
- Architecture viewing (Text/BDD/IBD tabs)
- PlantUML diagram generation
- Pair creation for training

## Architecture

```
┌─────────────┐
│  .json file │
└──────┬──────┘
       │
       ├─────────────> JSON IR dict
       │
┌──────▼──────┐
│ .sysml file │
└──────┬──────┘
       │
       └─> SysML Parser ──> JSON IR dict
                               │
                               ├──> PlantUML BDD
                               ├──> PlantUML IBD
                               └──> Display/UI
```

## File Detection

Files are identified as architectures if they:
1. Have `.json` or `.sysml` extension
2. Are in `data/architectures/` or `outputs/sysml/` directories

In the file tree, architecture files are highlighted in blue and clickable.

## SysML Parser

Located at: `spa/sysml_parser.py`

The parser extracts:
- **Package name** → `id`
- **Part definitions** → `blocks`
- **Ports** → `proxy_ports`
- **Requirements** → `requirements`
- **Connections** → `connectors`
- **Satisfy relationships** → `relationships`

### Supported SysML v2 Syntax

The parser handles the subset of SysML v2 generated by `json_to_sysml.py`:

```sysml
package arch_000001 {
  // Architecture Name
  // Domain: domain_name

  interface def InterfaceType;

  part def BlockName {
    port portName : InterfaceType;
  }

  requirement <'REQ-001'> {
    doc /* Requirement text */
  }

  part instance : PartType {
    part subpart : SubPartType;
    
    connection : linkName connect 
      partA.portA to partB.portB;
    
    satisfy requirement <'REQ-001'> by subpart;
  }
}
```


### Via API

```python
# Both endpoints work the same
GET /api/architecture/data/architectures/arch_000001.json
GET /api/architecture/outputs/sysml/arch_000001.sysml

# Both return JSON IR format:
{
  "id": "arch_000001",
  "name": "...",
  "blocks": [...],
  "proxy_ports": [...],
  ...
}
```

## Converting Between Formats

### JSON → SysML

```bash
python3 scripts/json_to_sysml.py
# Converts: data/architectures/*.json → outputs/sysml/*.sysml
```

### SysML → JSON (via parser)

```python
from spa.sysml_parser import parse_sysml_to_json

sysml_content = open('arch.sysml').read()
json_ir = parse_sysml_to_json(sysml_content)
```

## PlantUML Generation

Both formats generate identical PlantUML diagrams:

1. File loaded (`.json` or `.sysml`)
2. Parsed to JSON IR structure
3. JSON IR → PlantUML syntax
4. PlantUML rendered via public server

The PlantUML generation functions (`generate_bdd_plantuml`, `generate_ibd_plantuml`) work on the JSON IR structure, so format conversion is transparent.

## Training Workflow

### Recommended: Train on .sysml files

```bash
# 1. Generate varied JSON architectures
python3 scripts/generate_varied_architectures.py

# 2. Convert to SysML v2
python3 scripts/json_to_sysml.py

# 3. Use .sysml files for training
# Train Qwen adapter on outputs/sysml/*.sysml
```

### Alternative: Use JSON IR

```bash
# Train directly on JSON format
# Use data/architectures/*.json
```

**Why prefer .sysml for training?**
- It's the actual SysML v2 language (like training on Python, Java, etc.)
- Validates with official SysML v2 tools
- Can be used in SysML v2 modeling environments
- JSON is just an intermediate format

## Limitations

The SysML parser currently handles:
- ✅ Part definitions
- ✅ Ports with types
- ✅ Requirements with doc comments
- ✅ Connection definitions
- ✅ Satisfy relationships

Not yet supported (but in full SysML v2):
- ❌ Attributes with values
- ❌ Actions/behaviors
- ❌ State machines
- ❌ Allocations
- ❌ Complex expressions
- ❌ Constraints
- ❌ Calculations

To add support, extend `sysml_parser.py` with new extraction functions.

## Format Comparison

| Feature | JSON IR | SysML v2 |
|---------|---------|----------|
| **Purpose** | Intermediate representation | Official modeling language |
| **Validation** | Schema check | SysML v2 Pilot Implementation |
| **Tooling** | Custom scripts | SysML v2 ecosystem |
| **Training** | Possible | Recommended |
| **Readability** | Structured data | Domain-specific language |
| **Extension** | Add JSON fields | Add SysML syntax |

## Error Handling

If a `.sysml` file fails to parse:
- Server returns error JSON
- Check syntax against supported subset
- Validate with SysML v2 Pilot Implementation
- Review parser regex patterns in `sysml_parser.py`
